# Security review — October 30, 2026

Scope: source, scripts, packaging, local storage, process inspection, provider and financial network code, and a pattern-based scan of non-build workspace files. This is a source review, not an independent penetration test. At the time of this review, the workspace had no Git repository metadata, so commit history, tracked files, and GitHub repository settings were not inspected. No live credentials, bank connections, or privileged installation were tested.

## Fixes made during this review

- **Credential mix-up (high):** `LocalKeychain.secret` previously fell back to an arbitrary entry under the same service when the requested account was missing. A saved provider credential could consequently be sent to a different provider, or a ledger credential used in the wrong Plaid field. The lookup now requires an exact service and account; a regression test covers missing and empty account names. This fix does not affect an already-running older build until that build is updated. The review cannot determine whether a credential was actually sent to the wrong endpoint in the past.
- **Credential-bearing redirects (defense in depth):** provider, Plaid, and Jev requests now use an ephemeral session that refuses HTTP redirects, so credentials and request bodies cannot be forwarded to redirect targets. Provider endpoints that legitimately change their URL will need a code update.
- **Argument redaction:** `-H` and `-e` values are now omitted, and values for permitted options pass the same token filter as other arguments. The filter remains heuristic: process arguments and paths should be treated as sensitive.
- **Publication hygiene:** `.gitignore` now excludes common credentials, databases, diagnostic logs, JSONL, and generated test artifacts. This does not remove files already tracked or guarantee that a public repository is free of secrets.

## Open findings before public installation

1. **High — privileged installer trust boundary.** The app asks macOS to execute a shell script from the user-writable app bundle as root. The script verifies an ad-hoc-signed app and helper, then copies the helper to a root-owned location, but verification and copying use mutable source paths. A same-user attacker able to modify the bundle during installation could attempt to replace script or helper content, and ad-hoc identifiers do not establish a trusted publisher. Do not describe this as a secure public distribution mechanism. Design and independently test a signed privileged installation/update flow with immutable, trusted inputs, and test replacement/race and rollback scenarios. Basic monitoring works without the collector.
2. **High — provider sessions are discovered and used automatically.** Startup schedules provider refreshes that read Cursor, Codex, and Claude authentication material and local logs when available, then send credentials to their respective services. This is not an arbitrary third-party upload in the code reviewed, but it is sensitive behavior without a per-provider opt-in before first access. Add clear disclosure and per-provider consent before reading credentials or making requests; allow users to disconnect and stop future reads.
3. **Medium — distributed builds are ad-hoc signed.** Current scripts use `codesign --sign -`; that provides no publisher identity for someone downloading a release. Source builds and published binaries have different trust models. For distributed binaries, use Developer ID signing, hardened runtime where compatible, Apple notarization, and a reproducible, verifiable release process. Notarization and signing are not substitutes for review of the privileged helper.
4. **Medium — private local data relies on filesystem access controls.** The SQLite ledger contains transactions and holdings in plaintext, and history contains process names and paths. The ledger attempts to restrict the folder and SQLite files, but permission-setting errors are ignored; history is created before the ledger tightens the directory. Do not claim application-level encryption. Fail closed or make protection failures visible; decide whether additional encryption and backup guidance are needed.
5. **Medium — process inspection can reveal sensitive context.** Executable paths, working directories, open paths, and filtered command-line arguments may contain private information. Redaction is heuristic and cannot guarantee removal of all secrets. Local AI summaries are on device, but users can see and copy evidence. Explain this clearly and avoid presenting filtered output as guaranteed safe to share.
6. **Medium — publication content requires manual review.** `PROGRESS.md`, `VALIDATION.md`, `optimize.md`, and test fixtures include local usernames, paths, machine details, and development history. Review or remove these before publication if they are private. Scan the actual staged files and all Git history after initializing/importing the repository; ignored files already tracked or force-added can still be published. The pattern scan of non-build workspace text did not detect common OpenAI, GitHub, AWS, Slack, or PEM private-key patterns; it is not proof that no secrets are present.

## Protections observed

The root helper exposes sample and stop operations rather than a general command interface. It checks the configured user and applies a code-signing requirement to XPC connections. The helper configuration and install locations are intended to be root-owned and not group/world writable. Process termination is handled in the unprivileged app with a same-user check and PID/start-time revalidation. SQL values use bound parameters. Plaid/Jev network response bodies are not exposed in their error messages. Plaid and Jev require user configuration; Jev categorization has an explicit opt-in. None of these observations proves the app free of vulnerabilities.

## Validation and remaining work

The Swift suite passed 71 tests, including exact-account lookup, argument-redaction, and credential-redirect delegate checks; the release app built successfully. The redirect test checks the configured delegate directly, not a live network exchange. The native UI suite and a live privileged installation were not run during this review. Run static analysis and a purpose-built review of the privileged installer and XPC authorization on a disposable machine. Test a clean install, update, uninstall, denied authorization, multiple users, malformed inputs and race conditions. Obtain an independent security review before inviting others to install the privileged collector or connect sensitive accounts.
